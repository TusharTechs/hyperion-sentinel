This deliverable documents the primary outcomes of Task 4.3 (Open Resources Semantic Representation Models) and Task 4.4 (Application modelling for planning and triggering decision making). The main challenge addressed is the standardisation of application and resource descriptions across a diverse and distributed computing continuum. This is crucial for enabling the automated orchestration, scheduling, and lifecycle management.

The key contributions presented herein are:

1. A Structured, Kubernetes-Native Data Modelling Approach: The project made a strategic decision to move away from formal ontologies (e.g., OWL) towards structured, schema-validated data models using JavaScript Object Notation (JSON) and Yet Another Markup Language (YAML). This approach was chosen for its superior performance, simpler integration and reduced architectural complexity.

2. The Application Profile Manager (APM): As the principal outcome of T4.4, the APM is a software stack designed to create, validate, store, query, and update application profiles.

It provides a standardised, machine-readable format for describing an application's metadata, resource requirements (CPU, GPU, memory), Quality of Service (QoS) expectations, and deployment constraints. The APM includes a command-line interface (apmctl), a versioned schema registry, and a repository with a representational state transfer (REST) Application Programming Interface (API) for programmatic access.

3. Well-Defined Data Models: This deliverable specifies the data models for both node models and application profiles. a. Node Models provide a structured description of the capabilities of underlying infrastructure resources, enabling the matching and scheduling logic. b. Application Profiles are categorised into three types: native for container/ Virtual Machine (VM) workloads, device for hardware-centric edge/IoT applications, and integration for composing multi-component services.

4. A Reproducible Workflow: The APM establishes a clear, YAML-first workflow for developers and operators. This process—from initial template generation and schema validation to repository storage and secure API-based updates—ensures that all application descriptors are consistent, valid, and ready for consumption by higher-level orchestration and decision-making components within the HYPER-AI platform.

In conclusion, this deliverable provides the foundational models and tooling necessary for abstracting complex resource capabilities and application needs. The APM and its associated data models are critical inputs for WP5 and WP6, enabling the intelligent and automated management of applications across the HYPER-AI ecosystem.
