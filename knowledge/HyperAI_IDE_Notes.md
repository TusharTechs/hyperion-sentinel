HyperAI IDE overview (source: Veles Hack 2026 Challenge 1 description). The HyperAI IDE is the integrated development environment provided by HyperAI to help users build, run, and inspect AI workflows. Hyperion is the agentic assistant of this IDE: an LLM-powered chatbot that answers questions about HYPER-AI, controls the IDE frontend (create, edit and delete files) and acts on the user's behalf.

HYPER-AI project overview (source: Veles Hack 2026 Challenge 1 description). The HYPER-AI project aims to revolutionise distributed computing by addressing the complexities of integrating Internet of Things (IoT), Edge, and Cloud computing domains. It focuses on the creation of smart virtual computing nodes, optimising data-processing applications across a distributed network to enhance performance and efficiency.

Application profile formats in the HyperAI IDE (source: IDE workspace validator). The IDE validates two YAML profile formats, told apart by their root keys. A native application profile has an `applicationProfile` root and describes container or virtual-machine workloads. A device application profile has `apiVersion: hyper.ai/v1` and `kind: Application` and describes hardware-centric edge/IoT applications such as Android APKs, Docker images or ESP32 binaries.

Native application profile fields (source: IDE workspace validator). Required: metadata.type (native), metadata.schemaVersion (semantic version), metadata.name, metadata.version, metadata.owner, metadata.lifecyclePhase (development, testing or production); specs.runtime.executionType (container or vm), entryPoint, args, baseOS name and version, containerImage uri and tag; specs.resources cpu (millicores such as 2000m), memory (such as 4Gi) and storage; specs.network.ports with port and protocol; specs.constraints.supportedArchitectures. Optional sections include QoS (latencyToleranceMax in ms, availability in %, startupTime in s, resilience), constraints (securityLevel, dataClassification, trustScore from 1 to 5, geoLocationRequirement, isHighlyAvailable, faultTolerance) and platform-set status.

Device application profile fields (source: IDE workspace validator). Required: apiVersion hyper.ai/v1, kind Application, metadata.name, spec.app (type device, schemaVersion, name, version, owner, lifecyclePhase), and spec.workload.kind, which is one of AndroidApk, DockerImage or esp32Binary, with exactly the matching parameter block. Other sections cover spec.exec, spec.resources, spec.network, spec.qos, spec.constraints and spec.sensors.

Using the IDE (source: Hyperion starter and IDE backend). Files live in the IDE workspace file tree. Hyperion runs as a separate service on port 8000 and the IDE chat panel talks to its /chat endpoint, sending the user's prompt and a session id and receiving a streamed reply. When Hyperion creates, edits or deletes a file the IDE performs the change and refreshes the file tree; newly created or edited files open in the editor. The IDE can validate a profile file and highlight errors in the editor.
